Built *Lattice* — Indian Address Intelligence, on the Sarvam stack.

The problem: an Indian address isn't an address, it's directions.
"Ganesh mandir ke peeche, blue gate wala ghar, opp SBI ATM, Kothrud."
No street number, a temple as the reference point, four scripts.

Every geocoder assumes house → street → postcode, so it doesn't fail
loudly — it returns a confident pin 800m off. India's RTO rate is
15–30% vs 2–5% globally, and >45% of it is bad addresses.

What Lattice does:
• *Parse* — any script → structured fields, landmarks kept with their
  spatial relation
• *Resolve* — are these two differently-spelled records the *same
  physical door*? (validation APIs check one address; nobody answers this)
• *Score* — delivery risk before dispatch + the one field to ask for

Measured on 182,758 real bank-branch addresses: *precision 1.000, zero
false merges* vs 0.625 for string matching.

Three surfaces:
🔧 REST + voice API (speak an address in Hindi → JSON)
🤖 MCP server — agents call it as a native tool
📊 Console — drop a CSV, watch duplicates collapse into doors
